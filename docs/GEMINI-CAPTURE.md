# Пере-захват параметров протокола Gemini

Всё, что может устареть в веб-протоколе Gemini, лежит в одном файле:
`gemini-web.json`. Его можно заменить на телефоне **без пересборки** приложения.

## Когда это нужно

|Симптом в BookTrans|Что скорее всего устарело|
|---|---|
|`1060` при включённом VPN|ничего в файле; это блокировка по региону/IP|
|`1052` «Неверный model header»|форма `x-goog-ext-525001261-jspb` или поле `number` модели|
|`1050` «Модель не подходит»|`number` модели или набор моделей|
|Пустой список моделей|`rpc.status` (`otAQ7b`) или форма его ответа|
|«Нужно войти в Gemini» при живом логине|`wizKeys` или reject code, добавленный бэкендом|
|Перевод приходит, но не разбирается|модель изменила формат ответа — смотрите сырой ответ в Debug|

## Что снять

1. Откройте на компьютере <https://gemini.google.com> и войдите в тот же аккаунт.
2. **F12 → Network**, включите фильтр и напишите любое сообщение в чат, чтобы
   ушёл запрос.
3. В фильтре наберите `StreamGenerate`. Появится запрос вида
   `.../assistant.lamda.BardFrontendService/StreamGenerate?...`.
   Правый клик → **Copy → Copy as cURL**.
4. Отдельно снимите запросы к `batchexecute` (фильтр `batchexecute`) — они уходят
   при загрузке страницы и при открытии раздела с лимитами.

## Что выписать

Из cURL запроса `StreamGenerate`:

|Что|Где искать|Куда в `gemini-web.json`|
|---|---|---|
|`bl` (client build)|строка запроса, параметр `bl`|в `wizKeys` не входит; приходит со страницы, но полезно сверить|
|`f.sid`|строка запроса, параметр `f.sid`|то же|
|`x-goog-ext-525001261-jspb`|заголовок запроса|форма литерала в `GeminiProtocol.generateHeaders` (файл `Net/GeminiProtocol.swift`)|
|`x-goog-ext-525005358-jspb`|заголовок|там же|
|`x-goog-ext-73010989-jspb`, `x-goog-ext-73010990-jspb`|заголовки|там же|
|id модели|4-й элемент массива в `x-goog-ext-525001261-jspb` (16 hex-символов)|`models[].id`|
|`number` модели|15-й элемент того же массива|`models[].number`|
|`capacity`|12-й элемент того же массива|`models[].capacity`|
|`at`|тело запроса, параметр `at`|приходит со страницы (`SNlM0e`), в файл не пишется|
|индексы payload|тело `f.req`: это `[null,"<строка>"]`, внутри — массив из 81 элемента|сверить с §7.2 `docs/SPEC.md`|

Из запросов `batchexecute`:

|Что|Где|Куда|
|---|---|---|
|rpcid статуса аккаунта|параметр `rpcids` при `source-path=/app`|`rpc.status`|
|rpcid лимитов|`rpcids` при `source-path=/usage`|`rpc.usage`, `rpc.quota`|
|форма ответа статуса|тело ответа (фреймы `длина\nJSON`)|сверить с `parseAccountStatus` в `Net/GeminiResponse.swift`|
|форма ответа лимитов|то же|сверить с `parseUsage`|

Тело `f.req` декодируется так: это `[null, "<json>"]`, где второй элемент —
строка с массивом из 81 элемента. В Chrome можно выполнить в консоли:

```js
JSON.parse(decodeURIComponent(new URLSearchParams($0).get("f.req")))
```

## Как применить

### Быстрый путь (без пересборки)

1. BookTrans → **Настройки → Данные → «Записать gemini-web.json для правки»**.
   Файл появится в `Documents/Config/gemini-web.json`.
2. Откройте его в приложении «Файлы» (папка BookTrans) или скопируйте на
   компьютер, отредактируйте, верните на место.
3. Настройки → **Диагностика → «Перечитать параметры»**. Новый файл читается
   при запуске и по этой кнопке.

Если файл окажется битым, приложение не сломается: оно запишет предупреждение в
журнал и вернётся к встроенным значениям. Строка «gemini-web.json» на экране
диагностики показывает, что используется — встроенный файл или ваш.

### Постоянный путь (для всех)

Если новые значения стоит зашивать в сборку — правьте
`Packages/BookTransCore/Sources/BookTransCore/Resources/gemini-web.json` и
`Net/GeminiProtocol.swift`, затем `docs/SPEC.md` §7. Тест
`GeminiProtocolTests.testLastResortLiteralMatchesTheBundledResource` следит,
чтобы встроенный литерал и JSON не разошлись.

## Что смотреть при отладке

В приложении: **Настройки → Диагностика**.

- «Перечитать параметры» — какие `at`/`bl`/`f.sid` реально прочитаны со страницы
  и выполнен ли вход.
- Cookies: имена и возраст (значения не показываются и не логируются).
- Модели аккаунта и сырой ответ `otAQ7b`.
- «Тест: перевести 1 абзац» — один настоящий запрос и то, что вернул сервер.
- «Показать сырой ответ» — первые 4 КБ ответа и начало тела запроса.
- «Скопировать лог» — JSONL-журнал (`Documents/Logs/gemini.log`, ротация 2 МБ).
  Токен `at` и значения cookies заменяются на `<redacted>`: файл можно
  показывать посторонним.

**Лимиты**: Настройки → «Лимиты и тариф» — тариф и сырые ответы `jSf9Qc` и
`qpEbW`. Точные поля этих ответов не подтверждены, поэтому в интерфейсе видно
ровно то, что прислал сервер.
